# Preflight and dependency impact

`hostops preflight reboot` checks Docker boot enablement, running Caddy/restart policy, current site health, application restart policy, measured capacity, backup freshness, reported restore evidence and any reported backup in progress. `hostops preflight <site>` scopes the application checks to that property. Missing evidence prevents a green recommendation; confirmed blockers say not to proceed. Passing observations are still not a guarantee of successful maintenance.

`hostops impact caddy`, `hostops impact docker`, `hostops impact nginx`, `hostops impact host` and `hostops impact <site-or-workload>` simulate the discovered graph in automatic mode, including all mapped backends and each proxy. Proxy-served static sites inherit their proxy's runtime dependencies. The registered workflow uses its configured graph. Unresolved routes and hidden dependencies may expand the actual blast radius. No maintenance action is executed. Some reboot inspections remain Docker/Caddy-specific and cannot certify other boot behavior; unknown checks require operator review.
