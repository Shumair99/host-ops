# Security boundaries

Container permission checks collect bounded PID/parent/effective-UID/name observations. UID mappings distinguish container root from remapped host IDs. Nginx process titles are read only to classify master/worker roles, then discarded; raw arguments are never transmitted. Missing or incomplete process inventory remains unknown. A recognized root-supervisor/non-root-worker pattern retains the root warning and explains the roles. It is never exempted from least-privilege scoring.

Automatic backup discovery reads at most 512 header bytes from regular files inside backup-named folders under observed deployment directories and persistent mounts. It retains path, type, size and modification time, never file contents. Per-root entry/depth limits and artifact limits bound the scan. Standard recovery reports are read from the SSH user's private `~/.local/state/hostops/recovery` directory, capped at 64 KiB per file/256 entries, validated and projected into known fields; extra fields are discarded. Symlinks are not followed by these scans. Reported success is labelled as reported evidence, not independent restore attestation.

Dependency inspection reads local TCP endpoint tables and recorded Compose dependency labels. It sends neither environment values nor traffic payloads. Peer addresses and storage paths are private operational metadata. Network membership alone never becomes an application dependency; established connections and declared startup dependencies retain their separate evidence types.

HostOps is a local terminal application. It opens no management HTTP listener and uses no dashboard bearer token. Access is governed by the operating-system user, local file permissions and existing SSH credentials. The optional headless collector and watcher also expose no management server.

Collection does not restart containers, reload shared Caddy, prune resources or execute user-defined shell hooks. Docker inspections select metadata; environment values and raw health log output are omitted. Command errors do not echo raw stderr. Docker access remains powerful: a read-only Docker socket mount does not restrict the operations available through Docker's API.

Automatic connection uploads the matching Linux collector into the SSH user's owner-only cache, verifies its SHA-256 digest, and starts it over SSH stdio. The digest checks transfer integrity, not publisher identity: trust the local bundle before running it. The collector installs no service, exposes no port and exits when its input/session closes. HostOps does not enable Caddy/Traefik APIs, change proxy files or elevate permissions to fill coverage gaps.

## Optional always-on VPS history

The guided `hostops start` workflow can install a separate Linux systemd service after the operator chooses the always-on option. Installation requires working SSH key authentication and a trusted host key; a non-root SSH account also needs sudo authorization. A direct root SSH login is detected and runs the fixed installer without requiring the `sudo` program. HostOps does not request or store an SSH password or sudo password. The installer uses root briefly to create the `hostops` system account, a read-only `hostops-readers` group, a root-owned executable, a fixed systemd unit and a private state directory. It refuses to overwrite paths or accounts that already exist. `hostops agent uninstall` asks before removing the service and its retained history.

The running process has a no-login account, an empty capability set, `NoNewPrivileges`, a read-only system view and write access only to `/run/hostops` and `/var/lib/hostops`. Systemd limits its address family to Unix sockets. It does not bind TCP/UDP, run shell commands, inspect Docker, read site files or collect URLs, domains, environment variables, process arguments or credentials. It reads only Linux `/proc` CPU, memory, load and uptime counters plus root filesystem capacity metadata. Sampling is once per second; a bounded rolling history is checkpointed every 15 seconds and contains at most 128 samples / 256 KiB, with a 30-minute time window. The service uses one Go scheduler thread, an 8-task systemd ceiling and a 24 MiB Go runtime soft memory target; that target is not a hard RSS guarantee. The current cross-built executable is about 5 MiB; actual VPS resident memory and CPU use still need measurement on Linux.

The non-root SSH account that performed installation is added to `hostops-readers`, which grants access to the local Unix socket and this small history file only; a root SSH account already has access and is not added. The SSH bridge command is fixed and only relays bounded, versioned JSON frames; it accepts a host ID, not a command or path. Frames are validated for host identity, allowed metric names, value ranges, timestamps and size before they enter local SQLite. At most four bridge clients are served simultaneously. The local database follows the [finite history and size policy](history.md); the VPS copy stays limited to 30 minutes. Abrupt power loss can discard up to the last 15-second checkpoint interval.

SSH encrypts and authenticates transport to the host key already in `known_hosts`; strict host-key checking remains enabled. The SHA-256 check protects the uploaded executable from transfer corruption, but does not prove who published a release. Before distributing binaries publicly, releases should add signed provenance or checksums authenticated through a separate trusted channel. A root administrator or compromised VPS can alter or spoof telemetry; this service is monitoring evidence, not remote attestation. The local reader trusts the configured VPS identity and validates the data shape, not the honesty of the VPS.

Runtime labels, arguments and proxy configuration are parsed inside the collector. Only normalized facts are transmitted and persisted; Docker environment values, arbitrary labels, authentication middleware and raw config dumps are excluded. Podman inspection uses its complete JSON locally but projects selected facts before transmission. Upstream/redirect URL credentials and query strings are removed. Domains, paths, service names and selected image metadata remain potentially private operational data.

Remote inspections use SSH batch mode and strict host-key checking. Configuration and the connected VPS are trusted operator inputs. Public probes target discovered concrete proxy domains or explicit health preferences; the client is not a public endpoint accepting arbitrary untrusted URLs. Configured endpoint credentials and query strings are rejected. Private keys stay outside settings and Git. Public HTTP/TLS probes use the executing machine's network; they do not establish independent outage detection when executed on the monitored VPS.

Failing public endpoints can disclose their registrable parent domain to the HTTPS registry service listed by IANA for public RDAP evidence. Internal subdomain labels are omitted. This client has no cookies, credentials or environment proxy, verifies TLS, refuses redirects/nonstandard ports, rejects non-public destination IPs after resolution, and dials the validated IP. It retains only selected lifecycle/date fields and source/time metadata, never registration contacts or account information. Requests, responses, concurrency and caches are bounded. `HOSTOPS_NO_RDAP=1` disables this optional data sharing. Unavailable registry evidence cannot independently mark a website unhealthy. No RDAP result proves operator ownership or authorizes a repair. See [diagnostic semantics](diagnostics.md).

SQLite directories/files use restrictive POSIX modes. On Windows, HostOps installs protected ACLs granting the current account and SYSTEM access on new/empty history directories and SQLite database/WAL/SHM files. New SQLite sidecars inherit these directory permissions. Every existing nonempty directory is checked, including one named `local`: broad user/group access causes startup to refuse it instead of rewriting a shared project's permissions. Choose a new private database path with `--db` when needed; Windows reports a suggested location under the current account's cache directory. System administrators can still take ownership; this does not protect against a compromised operating system. Use SQLite-aware backups for an active WAL database. Deployment, backup, restore and watcher JSON files require the same protection as their destination database. Imports validate host/site scoping, allowed fields, size and chronology; no arbitrary commands or raw logs are accepted.

Operational text is reduced to printable ASCII before terminal rendering, preventing embedded escape sequences from controlling the terminal. Logs and capsules redact common credential patterns, but arbitrary application secrets can remain. Review local artifacts before sharing. Capsules retain names, IDs and public domains; exporting a capsule does not publish it.

The previous web frontend, API, token setup and listening port have been removed. `HOSTOPS_TOKEN` is unused. Optional watcher notifications use the separate `HOSTOPS_WEBHOOK` HTTPS destination; none is configured by default. HostOps stays outside the website request path.

Automatic storage inspection reads filesystem metadata and selected Docker size fields, without reading file contents or environment values. Its paths and sizes remain potentially private. Scans use existing SSH access, stay bounded and never invoke sudo or change permissions. Local execution, open source and ignored files do not guarantee user-only access; Windows history must reside in a directory with appropriate ACLs. See [storage inspection](storage.md) for automatic scheduling, overhead and ownership limits.
