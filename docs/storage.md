# Automatic storage inspection

Opening the interactive dashboard starts a background inspection when no current storage index is available. It waits for initial discovery on a connected server, then uses the observed inventory to associate directories and container writable layers with properties. The active page stays visible. Results live in the local SQLite history and are reused for 30 minutes; switching views and expanding directories does not run scans. Space in Disk explicitly requests another inspection. `--no-collect` and `host.disk_scan_disabled` disable automatic inspection. `hostops disk` uses the same inspection and cache boundary.

The scanner uses GNU/Linux `df`, `timeout`, `nice` and `du` plus available Docker metadata. The directory command is a single `du -x -0 -B1 --max-depth=8` traversal over selected roots, bounded by 45 seconds and run at CPU nice level 15. The total inspection has a 60-second context budget. Filesystem/inode and Docker reads have their own shorter budgets. Missing commands and inaccessible paths remain coverage gaps; HostOps does not install utilities or elevate privileges. Lower CPU priority does not impose an I/O bandwidth limit. A full metadata traversal can still cause storage activity and populate the OS cache.

By default, the root filesystem and observed ordinary local mounts are scanned. Virtual, overlay and network filesystems are excluded from automatic mount selection. Explicit `host.disk_roots` limits scope. Parent/child roots on one filesystem are deduplicated; a mounted filesystem gets its own traversal root. Symlinks are not followed by GNU du's default behavior. NUL-delimited results preserve unusual filenames; renderer sanitization prevents path text from controlling the terminal. The retained index is capped at 4,096 directories, prioritizing ownership targets and shallow/larger paths. Ancestor totals include descendants beyond the retained depth/index, but truncated paths cannot be browsed. Output is bounded at 4 MiB; a cut final record is discarded. Permission, timeout and output failures preserve available lower-bound measurements.

Disk displays filesystem capacity/inodes, a cached directory explorer with relative size bars, property-associated directories and writable container layers, Docker shared images/cache and growth between comparable complete inspections. Enter/Right opens a selected directory; Backspace goes to its parent; PageUp/PageDown scrolls the screen. Directory bars compare siblings to the largest visible directory, not to a sum of overlapping totals. Filesystem percentages follow df's used/(used+available) convention, accounting for blocks reserved from ordinary users.

Ownership comes from discovered backend mounts, observed document roots and configured runtime directories. Container document roots are translated through observed host mounts; image-only roots are never guessed to be host paths. Base/www pairs share one property, with shared backend layers counted once. Parent/child storage paths are collapsed within a property. Shared paths and backends are marked `*`; rows are not additive. A dash means there is no measurement, while 0 B is a measured zero. A missing layer size makes an otherwise measured property total a lower bound. Writable-layer sizes exclude image layers, mounted data and logs; Docker image/cache totals remain shared host accounting. This is storage evidence, not a billing allocation. Podman-specific layer accounting and physical fragmentation analysis are not implemented.

A SQLite lease prevents overlapping scans from dashboard processes using the same host/history database. The lease expires after a crash; canceled remote walks remain bounded by timeout. A failed inspection retains the previous index and retries after five minutes. Older shallow cache formats are refreshed automatically. Independent history databases do not share a lease.


## Local data and access

Storage scans inspect metadata rather than file contents. Paths, sizes, domains and runtime facts are nevertheless operational data. The terminal and history are local; SSH transports observations from the server and public probes contact website endpoints. No central telemetry service or hosted dashboard receives this evidence. Optional provider API reads and configured watcher destinations have their own documented network boundaries.

Use a private history directory. POSIX modes protect newly created history files on Linux. Windows now enforces protected current-user/SYSTEM ACLs for dedicated history directories and SQLite files; shared nonempty custom folders are refused. HostOps does not rewrite the enclosing project folder's permissions. Git ignore prevents accidental source commits, not local access. Open source makes the implementation reviewable; trust the installed executable and protect the SSH identity and history separately. See [security boundaries](security.md) and [history limits](history.md).
